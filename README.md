## ===== Підключення до MongoDB =====

Створіть свій кластер в mongodb та функцію connectMongoDB для встановлення зʼєднання з нею в окремому файлі src/db/connectMongoDB.js.

При створенні кластеру в MongoDB Atlas, не забудьте налаштувати доступ до мережі, щоб дозволити підключення з будь-якої IP-адреси. Для цього виконайте наступні кроки:

Увійдіть у свій обліковий запис MongoDB Atlas і перейдіть до свого проєкту.
Виберіть ваш кластер або створіть новий.
Перейдіть до розділу "Network Access".
Додайте новий запис до списку IP-адрес натиснувши кнопку "+ ADD IP ADDRESS".
У вікні, що з’явиться, виберіть "ALLOW ACCESS FROM ANYWHERE" або введіть 0.0.0.0/0 в поле "Access List Entry". Це дозволить підключення до вашого кластеру з будь-якої IP-адреси.
За потреби додайте коментар, потім натисніть "Confirm".

При вдалому підключенні до вашої бази в mongodb виводьте в консоль рядок "✅ MongoDB connection established successfully".

Дані для підключення до бази мають бути винесені в змінну оточення MONGO_URL.

Для роботи з mongodb використовуйте пакет mongoose.

У файлі src/server.js викличте функцію connectMongoDB . Переконайтеся, що зʼєднання із базою встановлюється до запуску серверу.

## ===== Middleware =====

Ваш додаток має використовувати стандартні middleware та бути грамотно організованим на рівні головного файлу src/server.js.

Створіть у папці src/middleware такі файли:

logger.js — логування HTTP-запитів за допомогою pino-http,
notFoundHandler.js — обробка всіх запитів на неіснуючі маршрути (повертає статус 404 та наступний об’єкт:

```javascript
{
message: 'Route not found',
}
```

errorHandler.js — глобальна обробка помилок: повертає статус 500, або інші статуси у разі використання бібліотеки http-errors та наступний об’єкт:

```javascript
{
message: повідомлення про помилку,
}
```

## ===== Головний сервер (src/server.js) =====

У файлі src/server.js:

1. Підключіть dotenv, express, cors
2. Викличте connectMongoDB() для встановлення з’єднання з базою даних перед запуском сервера
3. Підключіть middleware:
   middleware logger,
   express.json() для обробки JSON-тіла запитів,
   cors() для дозволу запитів з інших доменів, 4. Зареєструйте маршрути для роботи з колекцією нотаток (через notesRoutes.js)
4. Видаліть тестовий маршрут /test-error, який лишився з минулої ДЗ
5. Додайте middleware notFoundHandler після всіх маршрутів
6. Додайте errorHandler як останній middleware у стеку.

## ===== Модель Note =====

У папці src/models створіть файл note.js із Mongoose-схемою. Вона має містити поля:

title — обов’язковий рядок, з параметром trim: true
content — необов’язковий рядок (за замовчуванням порожній), з параметром trim: true
tag — приймає одне із фіксованих значень (Work, Personal, Meeting, Shopping, Ideas, Travel, Finance, Health, Important, Todo). Необов’язковий рядок (за замовчуванням Todo)

Для автоматичного створення полів createdAt та updatedAt, використовуйте параметр timestamps: true при створенні моделі. Це автоматично буде додавати до об'єкту два поля: createdAt (дата створення) та updatedAt (дата оновлення).

Імпортуйте базовий набір нотатків із файлу notes.json до вашої бази, користуючись будь-яким UI інтерфейсом (в браузері, Mongo Compass тощо). Переконайтеся, що назва колекції в коді моделі та в візуальному інтерфейсі співпадають.

## ===== Роут GET /notes =====

Створіть роут GET /notes, який буде повертати масив усіх нотаток. Обробка цього роута має включати:

Реєстрацію загального роута нотаток у файлі src/server.js. Не виносьте частину шляху /notes у server.js — вона має залишатися в описі роута.
Опис роута GET /notes у файлі src/routes/notesRoutes.js.
Опис контролера getAllNotes (не змінюйте назву контролера!) для цього роута у файлі src/controllers/notesController.js.
У разі вдалої обробки запиту відповідь сервера має бути зі статусом 200 та містити масив нотаток.

## ===== Роут GET /notes/:noteId =====

Створіть роут GET /notes/:noteId, який буде повертати дані нотатки за переданим ID або повертати помилку 404, якщо нотатка не знайдена. Обробка цього роута має включати:

Опис роута GET /notes у файлі src/routes/notesRoutes.js.
Опис контролера getNoteById (не змінюйте назву контролера!) для цього роута у файлі src/controllers/notesController.js.
У разі вдалої обробки запиту відповідь сервера має бути зі статусом 200 та містити об’єкт відповідної нотатки.
Додайте перевірку чи нотатка за переданим ідентифікатором була знайдена. Якщо нотатку не було знайдено, то використовуючи бібліотеку createHttpError поверніть відповідь зі сатусом 404 і повідомленням 'Note not found'.

На даному етапі не потрібно перевіряти невалідний MongoDB ID у цьому модулі. Припускаємо, що ID завжди валідний
